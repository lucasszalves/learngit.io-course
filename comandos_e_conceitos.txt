3 areas:

1 - working directory: arquivos em disco                                git commit -a |
    git add |                                                                 |    
            v                                                                 |
2 - staging area: arquivos selecionados para serem commitados                 |
    git commit |                                                              |
               v                                                              v
3 - repositorio: arquivos commitados e historico gravado

HEAD: ponteiro para o commit atual

merging: pega as incoming changes, agrupa elas todas de uma vez só (todas as modificações em cada commit da branch que vem) e adiciona no merge commit, como se aquilo tivesse sido feito tudo de uma vez só na branch que recebe
fast-forward merge: quando uma branch é criada e nada muda na original. quando for feito o merge da nova na original, o ponteiro da original só passa pro mesmo commit da nova (como se fosse um caminho único)
para cada conflito resolvido, faz um git add ou git rm para cada arquivo que teve erro para sinalizar pro git que foi resolvido, fica mais fácil de ver as resoluções no git status

remote: repositorio remoto (muitas vezes chamado de origin)
quando um repo é clonado, a pasta .git vem pro pc local

origin/main é simplesmente uma branch que vem da origem (remote reference pointer)
push: sincroniza mudanças locais para o remoto, joga origin/main para a main local
fetch: puxa as mudanças do remoto, mas só para a origin/main. o working directory não muda pq a main local ainda está desatualizada

quando o local e o remoto são diferentes, a main local diverge da origin/main, e essa é enxergada literalmente como uma branch diferente
para resolver, fazer merge normal, ou REBASE (colocar os commits locais a frente da origin/main, mantendo uma linha reta, e qdo as mudanças forem pushadas, o remoto vai fazer um fast-forward merge)


COMANDOS:
git log: mostra os commits, o hash completo e a mensagem
git log --stat: mostra quais arquivos foram modificados
git show <hash>: ver as linhas modificadas
git log --oneline: resumos dos commits, mostra só as mensagens e uma versão curta do hash (que pode ser usada pra acessar o commit)

git restore --staged <file>: unstageia arquivo
git restore <file>: desfaz alterações do arquivo MODIFIED, volta para o estado do último commit (PERDE AS MODIFICAÇÕES NÃO COMMITADAS), tipo um ctrl+z. não funciona para arquivos staged (usar flag --staged)

git commit --amend -m 'mensagem corrigida': corrigir mensagem do ÚLTIMO commit
git commit --amend --no-edit: não muda a mensagem do commit, só adiciona os arquivos STAGED ao último commit
git reset HEAD~1: volta um commit, e as modificações do último commit (que foi deletado), vão pro working directory (como se fosse voltar no tempo para logo antes de dar o commit)

comandos NOVOS (checkout == switch)
git branch <branch-name>: novo branch
git switch <name>: troca branch
git switch -c <name>: cria e muda a branch

git merge <incoming branch>: feito na branch que irá receber as modificações da incoming branch
git merge --abort: oque sera q faz em

git stash: pega todas as modificações STAGED e bota na stash (pilha)
git stash -m '<msg>': bota alterações na stash com nome
git stash list: lista das stashes
git stash show <index>: alterações da stash de indice index
git stash pop: coloca de volta as modificações da stash no topo no working directory
git stash pop --index <index>: coloca de volta a stash específica
git stash pop <index>: merma coisa
git stash branch <branch-name> <stash-index>: cria uma branch baseada na stash de index indicado
OBS.: PODEM TER MERGE CONFLICTS QUANDO COLOCADAS DE VOLTA!!

git clone <url>: https para configuraçao rapida (tem q digitar credenciais com frequencia), e ssh para autenticação mais segura e rápida (gerar par de chaves antes)
git clone --mirror <url>: cópia read-only
git remote -v: ver local do repo remoto
git branch --all: ver todas as branches do remote
git branch -vv: ver branches TRACKED (baixadas), por padrão só vem a main
